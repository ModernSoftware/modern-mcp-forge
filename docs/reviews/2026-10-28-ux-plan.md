## Behavior and boundaries

Visual fields support string, number, integer and boolean inputs. Existing field
constraints are retained; explicitly changing a field type resets its old type-specific
constraints. Nested structures and cross-field rules stay in JSON mode. Invalid or
duplicate names block save without discarding the draft. Definition and code drafts
survive tab changes; Test uses saved code and is blocked while either draft is dirty.

Code edits target the selected definition's declared worker module, which may be shared
by other items. The advanced source editor remains available for manifests and other
workers, including broken-startup repair. File revisions and project generations remain
mandatory. Saving still restarts project sources, so clients must reconnect.

New tools begin with an empty input schema and an explicit not-implemented business
error. Resource/prompt stubs return clearly labeled placeholder content. Only the
requested handler is generated; no unrelated greeting/guide/welcome handlers are added.
Existing project files are not rewritten. Renaming an existing public definition does
not rename its code or change its handler binding automatically; bindings remain visible.
Python function symbols use a `handle_` prefix to support public names such as `class`.

## Browser acceptance sequence

1. Create a project and check desktop cards, active state, search and narrow layout.
2. Choose Add tool. Name it `get_quote_by_sku`; verify the suggested source ID/path.
3. Add required `sku` string and `quantity` integer fields. Save directly.
4. Switch to JSON and back; verify names, required flags and existing validation survive.
5. Load a nested schema in JSON; requesting visual fields must preserve it and explain why.
6. Open Code; verify the named handler and JavaScript/Python contents, not stale JSON.
7. Implement the tool, save, then test it without selecting its source or name again.
8. Edit a field, switch tabs and attempt to leave/close. Decline discard; verify the draft remains.
9. Repeat with resources and prompts; disable an item and verify Test is unavailable.
10. In Advanced source files, switch between manifest and module; verify Monaco contents/language.
11. Edit a file externally; stale saves must fail while retaining the local draft.
12. Check light/dark themes, mobile layout, and project close returning MCP 503.
